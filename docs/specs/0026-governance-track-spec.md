# 提案與規格書：新增規範變更流程 (Governance Track)

> **狀態**：已核准（G2：使用者於 2026-11-19 核准，待決事項依建議決議）｜**類型**：規範變更（大改）｜**影響範圍**：規範文件與驗證腳本，不涉及 `src/`
>
> 本案是規範變更流程生效前的第一個規範變更，依本提案草擬的 G1 格式撰寫，作為新流程的首次試行。

## 一、動機

### 1. 分流表的缺口
[AGENTS.md](../../AGENTS.md) 第 2 節分流表目前有四類：簡單文件任務、功能開發、缺陷修正、緊急止血。修改規範本身（`AGENTS.md`、`CLAUDE.md`、`GEMINI.md`、`.agents/**`）不屬於其中任何一類，實際處理方式也不一致：

| 變更 | 實際走法 | 問題 |
| :--- | :--- | :--- |
| PR #15、#16（Gate 2 檢核項、QA 範本章節） | 當成簡單文件任務，不走閉環 | 分流表把簡單文件任務定義為「錯字、註解、說明」，但這兩次改變了 AI 的審查行為 |
| PR #17（Spec-0025 流程分軌） | 走功能開發流程 | PRD 的使用者故事、DDD 四層設計多半套不上 |

### 2. 規範變更特有的風險
規範改的不是系統行為，而是 **AI 自己的工作方式**，因此風險也不同。前四項在 PR #17 實際發生過：

| # | 風險 | PR #17 的實例 |
| :---: | :--- | :--- |
| 1 | 交叉引用失效 | 流程圖搬走後，AGENTS.md 開頭仍寫「使用下表指定的 Skill」 |
| 2 | 命名衝突 | 新的「Step 1B」與 ARCHITECTURE.md 既有標籤撞名 |
| 3 | 正本、轉接層、鏡像不同步 | `docs/templates/` 鏡像早已與正本不一致 |
| 4 | 鏡像斷鏈 | 範本內相對連結複製到 `docs/templates/` 後失效 |
| 5 | **自我核准** | 規範約束的是 AI；若 AI 提案、AI 審查、AI 放行，即為自我認證 |
| 6 | 常駐 Token 膨脹 | AGENTS.md 每次對話與每個子 Agent 都自動載入（目前 157 行、約 10,000 字元），每多一行，所有對話都要多付成本 |

## 二、變更內容

### 1. 新增 `.agents/workflows/governance.md`

**適用**：修改 `AGENTS.md`、`CLAUDE.md`、`GEMINI.md`，或 `.agents/**` 下的角色、技能、流程檔、範本、檢核清單，以及對應的 `.claude/**` 轉接層與 `docs/templates/` 鏡像。流程檔本身寫錯也走本流程，不走 Bug 軌。

| 步驟 | 內容 | 放行條件 |
| :--- | :--- | :--- |
| **G1 提案** | 寫下動機、要改的檔案、與既有規則的衝突或重複、規模判定（小改／大改） | 提案完整 |
| **G2 人類核准** | 由使用者確認提案與待決事項 | **只有使用者能放行**，AI 不得自行判定通過 |
| **G3 修改** | 只改正本；再同步轉接層、鏡像、索引 | — |
| **G4 一致性檢查** | 見下方檢查清單 | 全數通過 |
| **G5 審查** | 以獨立視角檢查規則之間有無矛盾、有無同一規則寫在兩處、用詞是否一致 | 零矛盾、零重複 |
| **G6 交付** | 小改：PR 描述記錄提案與檢查結果；大改：規格與 QA 報告 | — |

**G4 一致性檢查清單**：
1. `verify_doc_sync.py` 通過（轉接層、鏡像、分流表連結、索引）。
2. 全倉搜尋被改名、搬移或刪除的名稱與章節引用，確認無殘留（如「下表」「Step 1A」）。
3. 新名稱全倉搜尋，確認無撞名。
4. 回報 AGENTS.md 行數與字元數變化；增加超過 20 行須在提案說明理由。
5. 全倉 Markdown 斷鏈測試（`test_repository_markdown_links_resolve`）通過。
6. 若同時修改了程式（如驗證腳本），該部分須有單元測試，並另走 Gate 2 的程式檢查項。

### 2. 規模分級

| 規模 | 判定條件（任一成立即為大改） | 產出 |
| :--- | :--- | :--- |
| **小改** | 以下皆不成立 | PR 描述記錄 G1 提案與 G4 結果；不寫規格檔 |
| **大改** | 新增或刪除流程檔、技能、角色；搬移或重組章節；修改或放寬 AGENTS.md 第 1 節架構紅線；修改驗證腳本 | `docs/specs/XXXX-*.md` + `docs/qa_reports/XXXX-*.md`，與功能規格共用流水號 |

**紅線特別規定**：放寬或刪除第 1 節架構紅線，須由使用者在對話中**明確提出**，AI 不得主動提議放寬。

### 3. 分流表修改

| 請求類型 | 判斷條件 | 流程檔 |
| :--- | :--- | :--- |
| 簡單文件任務、問答 | 錯字、說明文字，**不改變任何規則或行為** | 不啟動閉環 |
| **規範變更**（新增） | 修改 `AGENTS.md`、`CLAUDE.md`、`GEMINI.md`、`.agents/**`，且不改 `src/` | `governance.md` |
| 功能開發、缺陷修正、緊急止血 | 不變 | 不變 |

同時修改 `src/` 與規範時，依 `src/` 的變更性質走功能開發或缺陷修正，規範部分併入該流程的 Step 7，並套用 G4 檢查清單。

### 4. 檔案清單

| 檔案 | 變更 |
| :--- | :--- |
| `.agents/workflows/governance.md` | 新增 |
| [AGENTS.md](../../AGENTS.md) | 分流表新增一列；修改「簡單文件任務」定義；開頭「閉環角色」段落同步修改簡單文件任務的描述 |
| [verify_doc_sync.py](../../.agents/skills/doc-sync/scripts/verify_doc_sync.py) | 新增 AGENTS.md 大小檢查：超過 200 行印出 WARN，不影響結束碼 |
| `tests/unit/`、`tests/e2e/test_workflow_tracks_doc_sync_e2e.py` | 新增大小檢查的單元測試；E2E 基準案例的流程檔數由 3 改為 4 |
| [docs/README.md](../README.md) | 索引登錄 |
| [REQUIREMENTS.md](../../REQUIREMENTS.md)、[ARCHITECTURE.md](../../ARCHITECTURE.md) | 流程分軌段落補上規範變更流程 |

不新增技能或角色：G1–G6 都是編排，作業細節沿用既有的 doc-sync 技能與 `verify_doc_sync.py`。
