# ADR-0028：閉環專案專屬值集中於 project.toml，規範文字以標記區分專屬規則

## 1. 狀態
已採納 (Accepted)

* **日期**：2026-11-20（提案與採納）
* **規格與驗收**：[Spec 0028](../specs/0028-portable-closed-loop-spec.md)、[QA Report 0028](../qa_reports/0028-portable-closed-loop-qa.md)
* **關聯**：[ADR-0016](./0016-github-pre-publish-security-and-pii-governance.md)、[ADR-0017](./0017-publish-privacy-scanner-hardening.md)（隱私掃描規則來源）
* **標籤**：`Governance`, `Portability`, `Config`, `Guardrails`

## 2. 背景與問題陳述
閉環規範（AGENTS.md、`.agents/**`）與兩支閘門腳本混雜通用原則與本專案專屬內容。腳本寫死分層路徑、豁免檔案、履歷檔名樣式與受保護身分指紋；`.gitignore` 必備清單同時寫在 AGENTS.md 紅線 7、review_checklist 與腳本三處。移植到其他專案時無法辨識該改哪裡，且整包複製會把本專案的個資指紋帶走。

本決策涉及紅線 1、6、7 與品質評測規則第 1 條的**文字**：具體路徑與清單改為指向設定鍵名。紅線**內容未放寬**。

## 3. 評估選項
* **A：另外維護一份去專案化的通用版**：本專案不動，但兩份規範會各自演變，每次修改都要同步。
* **B：就地重構，值集中於設定檔、專屬規則加標記**：本專案行為不變；移植時改一份設定、搜尋一種標記。
* **C：規範文字改用 `{{...}}` 模板語法並加渲染步驟**：一致性最高，但 AI 讀到的是未渲染的佔位符，需額外工具鏈。

## 4. 架構決策
採納 **B**：
1. **設定正本**：`.agents/project.toml` 存放所有「換專案只變值」與「規則專屬且由腳本檢查」的值，以標準庫 `tomllib` 讀取；共用讀取模組為 `.agents/lib/project_config.py`。
2. **明確失敗**：缺檔、缺鍵或型別不符時，兩支腳本以結束碼 2 中止並指出缺漏，不提供隱含預設值。
3. **豁免附理由**：`guardrails.url_exceptions` 每筆必填 `reason`，理由與豁免放在同一處。
4. **DDD 開關**：`layers.enabled = false` 時略過 Domain 純潔性與 Application DIP 檢查，其餘檢查照常。
5. **文字引用方式**：以職責指稱並註明設定鍵名，括號內保留本專案現值（如「Domain 契約檔（`layers.domain_interfaces`，本專案為 `src/domain/interfaces.py`）」）。
6. **專屬規則標記**：以 HTML 註解 `<!-- 專案專屬 -->` 或 `<!-- 專案專屬：說明 -->` 標記，渲染時不可見；紅線不重新編號，以保留歷史文件的「紅線 N」引用。
7. **工作區路徑檢查**：改由 `ROOT_DIR` 實際路徑動態組出樣式，不進設定。

## 5. 8 大架構審查維度評估
本案為規範與驗證腳本變更，不涉及 `src/`；與執行期相關之維度（容量、非同步、索引演進、併發）不適用。個資隱私維度：受保護身分指紋移入設定，移植指南明定必須清空。詳見 [Spec-0028](../specs/0028-portable-closed-loop-spec.md)。

## 6. 後果
* **正面**：移植只需改寫 `project.toml` 並處理標記處；`.gitignore` 必備清單收斂為一處；豁免理由可稽核。
* **負面**：腳本多一層設定讀取；規範文字在本專案閱讀時多了括號內的設定鍵名。
* **風險**：新增專屬規則時忘記加標記。緩解：G5 審查時檢查新增規則是否屬專案專屬。
