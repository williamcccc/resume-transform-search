# ADR-0037：AGENTS.md 紅線分為通用與本專案兩組，專案事實集中於實例檔

## 1. 狀態
已採納 (Accepted)

* **日期**：2026-11-21（提案與採納）
* **規格與驗收**：[Spec 0037](../specs/0037-project-profile-tests-and-red-lines-spec.md)、[QA Report 0037](../qa_reports/0037-project-profile-tests-and-red-lines-qa.md)
* **關聯**：[ADR-0028](./0028-portable-closed-loop-project-config.md)（專屬值集中於 project.toml、規則以標記區分）
* **標籤**：`Governance`, `Portability`, `Red Lines`

## 2. 背景與問題陳述
AGENTS.md 第 1 節「核心不可變紅線」7 條中，第 2～5 條為本專案專屬（CLI 相容、Word 補樁與索引冪等、品管閥 65 分、Text-First），與通用紅線 1、6、7 交錯排列，並以 6 處逐行標記區分；紅線 7 第一點同時寫入通用規則與本專案敏感資料類型。AGENTS.md 每次對話自動載入，是閉環的憲法檔；移植時須在其中逐條辨識哪些是本專案規則，風險是誤刪通用紅線或遺留本專案紅線。

## 3. 評估選項
* **選項 A：紅線搬至專案實例檔**（`.agents/project/`）。AGENTS.md 只留通用紅線。缺點：實例檔不會自動載入，本專案紅線可能在對話中未被讀到，削弱紅線效力。
* **選項 B：AGENTS.md 內分組，保留原編號**。通用紅線與本專案紅線各成一小節；以「紅線 N｜標題」標示，保留 1–7 編號。缺點：編號在兩組間不連續。
* **選項 C：AGENTS.md 內分組並重新編號**（通用 1–3、專案 P1–P4）。缺點：倉內 22 處歷史文件以編號引用紅線，需逐一改寫或附對照表。

## 4. 架構決策
選用**選項 B**。

* 第 1 節分為「通用紅線（任何專案適用）」與「本專案紅線（移植時整節改寫）」；本專案紅線小節以單一整節標記標示，取代原 6 處逐行標記。
* 紅線 1–7 規範文字逐字保留（以比對腳本驗證 12 段原文全數存在）；只改編排與標示方式。以「紅線 N｜標題」取代 Markdown 有序清單，避免編號不連續時被渲染器自動重新編號。
* 紅線 7 第一點拆為通用敘述（真實個資、敏感目錄以 `privacy.sensitive_dirs` 表示）與「紅線 7 本專案補充」（原文完整保留：求職者、履歷、`data/`、`resume/`）。本專案的實際約束不變，未放寬。
* 「本專案執行環境」（Python 3.13 on Windows）由第 4 節移入本專案紅線小節，維持常駐載入。
* 描述性專案事實（入口、主要流程、持久化結構、敏感資料類型、測試環境）集中於 `.agents/project/profile.md`，供技能引用；不放 AGENTS.md，以免常駐載入內容膨脹。

本決策由使用者於 2026-11-21 明確提出並核准，符合 [governance.md](../../.agents/workflows/governance.md)「紅線特別規定」；未放寬或刪除任何紅線。

## 6. 後果
* **正面**：移植時只需改寫「本專案紅線」一節與 `.agents/project/` 實例檔；AGENTS.md 與 `.agents/`（實例檔除外）之專屬標記只剩一處整節標記。
* **負面**：紅線編號在兩組間不連續（通用 1、6、7；本專案 2–5）；以小節說明「編號為固定識別碼」緩解。
* **後續**：新專案可視需要於本專案紅線小節新增紅線，編號自 8 起接續，不重用 1–7。
