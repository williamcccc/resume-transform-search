# ADR-0017: 上庫前個資掃描與文件連結防線補強

## 1. 決策狀態

* **狀態**：已採納 (Accepted)
* **日期**：2026-11-05
* **決策負責人**：Development Team
* **標籤**：`Privacy`, `Static Scanning`, `Git Hygiene`, `Documentation`
* **規格與驗收**：[Spec 0017](../specs/0017-github-publish-privacy-and-link-hardening-spec.md)、[QA Report 0017](../qa_reports/0017-github-publish-privacy-hardening-qa-report.md)

## 2. 背景與問題陳述

既有上庫掃描以特定完整文字的雜湊前綴為主，無法偵測部分遮蔽的 CJK 識別字串或個人化履歷檔名。掃描器也沒有檢查 Email、電話、身分識別碼或 Markdown 本機連結。舊規格與 QA 報告因此對隱私清零作出超出實際覆蓋範圍的保證。

## 3. 評估之架構選項

### 選項 A：只清理已知文件內容

* **優點**：變更範圍小。
* **缺點**：相同類型的殘留可能再次進入文件或測試，缺少回歸防線。

### 選項 B：外接個資辨識服務

* **優點**：可辨識更多未知格式與語言的個資。
* **缺點**：需要把候選文字交給外部服務，增加資料外傳、設定及維護成本。

### 選項 C：擴充本機確定性掃描並安全回報（選定）

* **優點**：離線執行、不傳送文件內容，針對已知失敗型態增加測試；輸出不包含命中原文。
* **缺點**：啟發式規則仍無法證明所有未知個資格式均已清除，需維持人工覆核。

## 4. 最終決策結果

採用選項 C。掃描器除了既有指紋比對外，新增遮蔽 CJK 識別字串、個人化履歷檔名、Email、電話及台灣身分識別碼標記；掃描檔案路徑與可讀文字，錯誤只回報路徑和類別，若路徑本身命中隱私樣式則以佔位符取代。單元測試以記憶體合成資料驗證命中及通用樣本允許規則。Markdown 文件連結測試略過 fenced code block 與外部連結，確認其餘本機目標存在且留在專案內。

本機生成輸出維持在 `.gitignore` 排除目錄；範例路徑使用行內程式碼，不要求將履歷樣本加入 Git。舊規格與 QA 報告修正為不含來源識別資訊，並明確記錄原始掃描結論已被取代。

## 5. 8 大架構審查維度評估

1. **個資隱私 (PII & Data Privacy)**：掃描只在本機執行；命中內容不寫入終端或報告，測試夾具於記憶體合成。
2. **容量與極限 (Capacity & Limits)**：維持現有專案文字掃描方式，額外正則成本隨輸入長度線性增加。
3. **非同步與演進 (Async & Evolution)**：不涉及執行時非同步流程。
4. **成本與熔斷 (Cost & Circuit Breaker)**：不呼叫外部服務，不產生 Token 或 API 費用。
5. **無損與容錯性 (Fail-Safe & Lossless Integrity)**：不讀寫、搬移或修改履歷輸入資料；讀取錯誤仍沿用掃描器既有安全處理。
6. **可稽核性 (Auditability & Observability)**：違規輸出相對路徑與類別，不輸出命中值。
7. **向下相容性 (Backward Compatibility)**：不變更 CLI、API 或執行時資料格式。
8. **安全性與注入防護 (Security & Jailbreak Defense)**：忽略目錄與 `.env` 排除規則維持不變，且 Markdown 連結檢查不開啟或執行連結目標。
