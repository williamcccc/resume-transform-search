# ADR-0004: 建立確定性品管閥與獨立評審員四層品管防線

## 1. 狀態
已採納 (Accepted)

## 2. 背景與問題陳述 (Context & Problem Statement)
使用大語言模型（LLM）處理履歷時，有不可避免的幻覺風險（如過度精簡摘要、胡亂猜測聯絡資訊、遺漏核心公司經歷）。
如果沒有客觀把關機制，錯誤的 Markdown 檔案一旦寫入磁碟並被索引進 Redis，將污染後續的 RAG 招募檢索結果。

## 3. 評估選項 (Options Evaluated)
* **選項 A：完全信任轉檔產出**：零檢驗成本，但嚴重缺陷檔案直接流向終端使用者，產生致命業務風險。
* **選項 B：全交由第二個 LLM 再次評分**：彈性高，但成本翻倍，且 LLM 評審本身也存在隨機性。
* **選項 C：四層防禦體系（確定性品管閥 ＋ 獨立評審員 ＋ 自動隔離 ＋ CSV 批量稽核，推薦）**：
  * 防線一：確定性品管閥（`MarkdownQualityValidator`）以純演算法檢查 H1、結構、字數保留率、實體召回（Email/手機）。
  * 防線二：可選獨立評審員（`LLM-as-a-Judge`），按 5 大維度評分並輸出 JSON 評分卡。
  * 防線三：自動隔離區（Quarantine），低於 65 分強制移入隔離區，不污染輸出目錄。
  * 防線四：批次轉檔 CSV 稽核日誌，全面記錄品質指標供人工覆核。

## 4. 架構決策 (Decision Outcome)
**採納選項 C**。
* 任何產出必須經過確定性檢核，分數 $<65$ 視為轉檔失敗。
* 透過依賴反轉將評審契約定義於 `IQualityValidator` 與 `ILlmJudge`。

## 5. 5 大架構審查維度評估 (Architecture Review Analysis)
1. **個資隱私 (PII)**：檢核閥會自動比對原始檔案與轉檔產出中的 Email 和手機號碼，確保核心個資無遺漏亦無偽造。
2. **容量與極限 (Capacity)**：確定性品管閥以純字串與正則表達式比對，耗時不到 1 毫秒，記憶體零開銷。
3. **非同步與演進 (Async / Evolution)**：檢驗結果以 `QualityReport` 值物件封裝，方便在微服務或批次流程中傳遞。
4. **成本與熔斷 (Cost & Circuit Breaker)**：品管閥以本地程式為主，僅在開啟 `--judge` 時呼叫 LLM，最大化降低成本。
5. **可抽換性 (Portability & Decoupling)**：隔離與稽核路徑均由參數動態注入，可隨時替換或掛載於雲端儲存空間（S3 / GCS）。
