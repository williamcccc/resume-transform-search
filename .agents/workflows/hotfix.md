# 緊急止血流程 (Hotfix Track)

> **適用**：嚴重度 S1 的缺陷——資料損壞或遺失、個資外洩、安全漏洞、主要流程（轉檔、檢索<!-- 專案專屬 -->）全面失敗。
> 以 [bug.md](./bug.md) 為基礎，**只列出縮減與追加之處**；未提及的步驟與規則（含 PR 與 commit 規則、升級條件）照 bug.md 執行。

## 與 bug.md 的差異

| 步驟 | 縮減方式 | 不可省 |
| :--- | :--- | :--- |
| **1B** | RCA 可先寫摘要；簡化 Gate 1 可於合併後補簽 | 重現、紅燈回歸測試 |
| **2–3** | — | 紅燈測試轉綠、全套單元測試無回歸 |
| **4 QA** | 縮為受影響範圍的冒煙測試 | — |
| **5 Gate 2** | — | **完整執行**（`audit_guardrails.py`、`security_scan.py` + Checklist） |
| **7** | 缺陷報告與 `docs/README.md` 缺陷索引先標「已止血，待補件（期限 YYYY-MM-DD）」，期限為合併日加 3 個工作天 | — |

## 合併後補件
合併後 **3 個工作天內**補齊：
1. 完整 RCA 與逃逸分析（缺陷報告第 3 節）。
2. 完整 QA 報告（範圍涵蓋受影響功能，非僅冒煙測試）。
3. 簡化 Gate 1 簽核（若合併前未簽）。

補件完成後，缺陷報告改標「已結案」。

## 根治需升級
止血與根治分兩段：
1. **止血**（本流程）：不碰介面的最小防護，例如輸入檢查並明確拒絕、關閉該功能、遮蔽輸出，快速合併。
2. **根治**：開新功能規格，走 [feature.md](./feature.md)；缺陷報告標「已止血，根治見 Spec-XXXX」。

若連止血都必須修改介面或資料模型，停止流程，交由使用者決定。
