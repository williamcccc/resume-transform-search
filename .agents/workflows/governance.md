# 規範變更流程 (Governance Track)

> **適用**：修改 `AGENTS.md`、`CLAUDE.md`、`GEMINI.md`，或 `.agents/**` 下的角色、技能、流程檔、範本、檢核清單，以及對應的 `.claude/**` 轉接層與 `docs/templates/` 鏡像，且不改 `src/`。流程檔本身寫錯也走本流程，不走 Bug 軌。
> 同時修改 `src/` 時，依 `src/` 的性質走 [feature.md](./feature.md) 或 [bug.md](./bug.md)，規範部分併入其 Step 7，並套用本檔 G4 檢查清單。
> **本檔只寫編排**；文件同步與驗證的作業細節以 [doc-sync](../skills/doc-sync/SKILL.md) 為準。

## 步驟

| 步驟 | 內容 | 放行條件 |
| :--- | :--- | :--- |
| **G1 提案** | 寫下動機、要改的檔案、與既有規則的衝突或重複、規模判定（小改／大改）、待決事項與建議 | 提案完整 |
| **G2 人類核准** | 由使用者確認提案與待決事項 | **只有使用者能放行**，AI 不得自行判定通過 |
| **G3 修改** | 只改正本；再同步 `.claude/**` 轉接層、`docs/templates/` 鏡像與 `docs/README.md` 索引 | — |
| **G4 一致性檢查** | 見下方檢查清單 | 全數通過 |
| **G5 審查** | 以獨立視角檢查：規則之間有無矛盾、同一規則有無寫在兩處、用詞是否一致 | 零矛盾、零重複 |
| **G6 交付** | 小改：PR 描述記錄 G1 提案與 G4 結果；大改：規格與 QA 報告 | — |

退回路徑：G4 或 G5 未通過 → 回 G3 修正；修正改變了提案範圍 → 回 G1，並重新經 G2 核准。

## G4 一致性檢查清單
1. `verify_doc_sync.py` 通過（轉接層、鏡像、分流表連結、索引）。
2. 全倉搜尋被改名、搬移或刪除的名稱與章節引用，確認無殘留（如「下表」「Step 1A」）。
3. 新名稱全倉搜尋，確認無撞名。
4. 回報 AGENTS.md 行數與字元數變化；增加超過 20 行須在提案說明理由；超過 200 行時 `verify_doc_sync.py` 會印出 WARN，應考慮把內容移到流程檔或技能。
5. 全倉 Markdown 斷鏈測試（`tests/unit/test_github_pre_publish_hygiene.py` 的 `test_repository_markdown_links_resolve`）通過。
6. 若同時修改了程式（如驗證腳本），該部分須有單元測試，並另走 Gate 2（[gate2-code-review](../skills/code-review/SKILL.md)）的程式檢查項。

## 規模分級

| 規模 | 判定條件（任一成立即為大改） | 產出 |
| :--- | :--- | :--- |
| **小改** | 以下皆不成立 | PR 描述記錄 G1 提案與 G4 結果；不寫規格檔 |
| **大改** | 新增或刪除流程檔、技能、角色；搬移或重組章節；修改或放寬 AGENTS.md 第 1 節架構紅線；修改驗證腳本 | `docs/specs/XXXX-*.md` + `docs/qa_reports/XXXX-*.md`，與功能規格共用流水號 |

大改不另寫 ADR；只有修改架構紅線時，才於 `docs/adr/` 記錄決策。

## 紅線特別規定
放寬或刪除 AGENTS.md 第 1 節架構紅線，須由使用者在對話中**明確提出**；AI 不得主動提議放寬紅線。
